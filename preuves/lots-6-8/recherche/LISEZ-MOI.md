# Recherche documentaire — lot 6

Les preuves définitives sont dans [validation.json](validation.json) et [tests.log](tests.log). Le script [validate.py](validate.py) peut être relancé avec le Python du projet ; il travaille exclusivement dans des dossiers temporaires et refuse un résultat définitif si les sources suivies changent pendant les essais.

Validation définitive sur les sources finales : **94 tests réussis en 154,08 secondes**, empreintes identiques avant/après. Répartition : 11 nouveaux tests documentaires, 28 tests Workspace existants, 5 tests de workers, 12 tests d’historique, 28 tests de sauvegarde et 10 tests de restauration. Les cinq questions contrôlées retrouvent toutes le bon document en première position et la réponse dans l’extrait exact ; les requêtes durent de 5,41 à 6,29 ms. Le document de 460 075 caractères produit 288 passages, indexés en 32,60 ms ; sa réponse située en fin de document est retrouvée en 9,22 ms. Le PDF de deux pages est extrait en sous-processus en 294,92 ms et cite la page 2. Ces durées décrivent cet essai isolé sur ce poste.

Empreintes finales vérifiées : `workspace.py` = `f4f3a90f0723586b3b6f625bb5bfc893ec6a96b6b990fd7722f58dd46da57d68` ; `notifications.py` = `a948d01c072f7dfd4eace6bc2bef08cb1c6db6efd89380e583cc0e11e4e8e7a9`. Le rapport JSON contient aussi l’empreinte du jeu de tests et les valeurs non arrondies.

La recherche conserve SQLite FTS5. Elle retire les mots courants des questions françaises, privilégie la couverture des termes utiles puis le classement BM25, et filtre le propriétaire, le projet et le document sélectionné avant de limiter les candidats. Elle retourne au maximum six passages littéraux de 1 800 caractères. Les clauses proches avec des dates ou montants différents restent distinctes. Une absence de résultat est explicite. Une demande de résumé/traduction d’un document sélectionné peut utiliser ses premiers passages ; une question précise sans correspondance conserve l’absence de source.

Les cinq questions de référence vérifient le document en première position, la réponse présente dans l’extrait exact et l’absence de page inventée. Cette mesure est un petit jeu contrôlé, pas une garantie générale sur toutes les questions. Le cas long recherche une information placée après 460 000 caractères, y compris après 55 documents concurrents. Le PDF possède deux vraies pages ; l’extraction s’exécute dans le sous-processus borné existant et la citation correcte porte la page 2. TXT, Markdown, DOCX et notes ne reçoivent aucun numéro de page.

Chaque source expose `source_id`, `document`, `project`, `title`, `page`, `text`, `revision`, `version`, `excerpt_hash` et `status`. La consultation authentifiée utilise l’action `source_get` avec `source_id` sur le transport Workspace existant. Elle vérifie le propriétaire, conserve l’extrait de la version utilisée et signale `current`, `modified` ou `unavailable`. Les anciennes citations conservent leur extrait même si le document courant est supprimé. Les résultats de tâches gardent leurs références et leur version dans leur JSON persistant.

Le catalogue de références est dédupliqué et limité à 2 000 références par propriétaire, 12 000 au total. Les références comptent dans les quotas de données et les sauvegardes. Les résultats de tâches conservent une copie indépendante : leur consultation reste possible après éviction du catalogue tant que la tâche est conservée. Les droits ne donnent jamais accès à une source d’un autre propriétaire, même avec son identifiant exact.

Les documents et les instantanés d’espace exposent l’état d’indexation, le nombre de passages, la version indexée et la date. Le nombre total de pages d’un ancien PDF reste inconnu lorsqu’il ne peut être déduit avec certitude ; les pages des passages existants sont conservées. Un index FTS périmé est reconstruit au redémarrage à partir des passages actuels. Les archives anciennes sont reconnues par leur schéma exact puis migrées avec les seules instructions installées ; aucun SQL provenant d’une archive inconnue n’est exécuté. Les archives vérifient aussi les propriétaires, les liens de projet, les versions, les empreintes et la fidélité des citations courantes.

Les limites d’origine restent 2 Mo par fichier, 500 000 caractères extraits, 20 Mo par propriétaire par défaut et 128 Mo au total. Les notifications de document prêt et de tâche terminée utilisent la même transaction SQLite ; une réserve de 600 octets protège leur comptabilisation. Les sauvegardes, la restauration, la maintenance et la sérialisation des workers font partie des régressions isolées. Aucun OCR, moteur sémantique ou accès à la production n’a été utilisé pour ces preuves.
