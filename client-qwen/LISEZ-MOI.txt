Accès serveur Fred — version 3.5.23

WireGuard utilise un emplacement permanent dans %LOCALAPPDATA%\AccesServeurFred\WireGuard.
Windows conserve ainsi l'autorisation entre les lancements. Une première autorisation
peut être nécessaire pour cet emplacement ou si le moteur WireGuard change.

Lancez l’EXE personnel remis par le serveur. Il contient les clés du destinataire
et demande au premier lancement de choisir Internet (HTTPS) ou WireGuard. Aucun compte ni mot de passe à saisir.
Chaque destinataire possède un accès distinct, révocable depuis la console serveur.

La fenêtre est organisée par fonction :
- Conversations : chatbot intégré, recherche, renommage, suppression avec annulation,
  copie des messages, import/export, réflexion, arrêt et nouvelle tentative.
  Glissez une discussion sur un projet dans la barre latérale ou dans Projets pour
  la déplacer. Le clic droit propose Déplacer, Archiver, Restaurer et Supprimer.
  Le filtre Archivées retrouve les discussions conservées. Annuler la suppression
  restaure aussi leur publication dans le projet, pendant la session courante.
- Projets : discussions publiées, consignes, documents éditables, fichiers et mémoire choisie.
- Correcteur : texte français, correction grammaticale et orthographique, reformulations
  professionnelle ou amicale, copie et conservation des résultats.
- Tâches : travail serveur client fermé, résultats, pause, annulation et planification.
- Réglages : accès personnel, connexion, mises à jour et API locale pour les autres applications.

Sélectionnez le texte affiché ou le contenu d’un champ, puis utilisez Ctrl+C,
le bouton « Copier la sélection » dans l’en-tête ou le clic droit > Copier la sélection.
Le clic droit propose aussi « Tout sélectionner dans cette zone ».
La sélection reste possible pendant une réponse ou une correction en cours.

Le bouton Réflexion, à côté de « Sans projet », ouvre une barre de sélection :
Sans, Faible, Moyen, Élevé. Elle affiche les niveaux annoncés par le serveur.
Le choix est conservé après fermeture et envoyé avec la prochaine demande.

Dans le chat, choisissez un projet. Les passages utiles des documents
du projet alimentent la réponse et s'affichent avec leurs références. Toutes les conversations sont enregistrées automatiquement
sur le serveur, même sans projet. Enregistrer au projet ajoute une discussion au
projet choisi. Une copie locale chiffrée conserve les modifications hors connexion
et se synchronise à la reconnexion, sans écraser les changements d'un autre poste.

Projets accepte TXT, Markdown, DOCX et PDF texte, jusqu'à 2 Mo. Les PDF scannés
demandent un OCR préalable. Les notes s'enregistrent automatiquement avec contrôle
de révision ; les brouillons sont chiffrés localement. Comparez avec le serveur en
cas de conflit. Une révision proposée par l'IA doit être acceptée avant de remplacer
le document. Les fichiers et projets du serveur sont accessibles à son administrateur.

Les tâches restent disponibles client fermé. Les tâches interrompues par une panne
attendent une relance explicite. La recherche web nécessite une autorisation serveur ;
avec une URL HTTPS publique, aucune clé de recherche n'est nécessaire. La recherche
par sujet utilise une clé Brave configurée sur le serveur. Les exports sont en texte
ou Markdown. Voir ../lanceur/ESPACES-FRED.txt pour les limites et réglages.

Dans Réglages > Connexion, choisissez WireGuard ou HTTPS Cloudflare, puis
Appliquer la connexion. HTTPS utilise https://ia.karenax.net et le même accès personnel.
Cloudflare termine le chiffrement HTTPS et peut techniquement lire les données.
Ce choix est conservé pour votre compte Windows ; aucun basculement automatique
vers Cloudflare ne se produit. Aucune connexion ne démarre avant ce premier choix.

Automatique privilégie le réseau local quand il est utilisable, puis l’adresse Internet.
Dans la console serveur, Accès distant > Copier les paramètres pour le client distant
copie l’adresse et le port UDP. Dans le client, Réglages > Connexion > Coller les
paramètres prépare l’adresse ; Appliquer l’adresse la valide et se reconnecte.
Le collage manuel avec Ctrl+V fonctionne également dans l’adresse ou dans la zone
des paramètres. L’accès personnel intégré à l’EXE reste nécessaire.
Le nom annoncé par le modèle chargé reste visible dans l’en-tête de toutes les vues.
Dans Réglages > API locale, Ajouter à OpenCode 2 et Ajouter à Hermes détectent
les applications installées sur ce PC et ajoutent le fournisseur Serveur Fred.
Choisissez ensuite ce fournisseur et le modèle dans l’application concernée.
Gardez le client Fred ouvert ; relancez l’application si la liste n’est pas actualisée.
Le modèle par défaut et les autres fournisseurs restent conservés. Une sauvegarde
.fred-backup est créée à côté de la configuration avant chaque modification.
Seule la clé API locale est transmise à ces applications, avec l’adresse locale
et le nom du modèle. La connexion choisie reste gérée par le client Fred.
Sur le serveur lui-même, il essaie localhost. La clé publique du serveur reste vérifiée
après un changement d’adresse. Les modèles sont annoncés par le serveur.
Le diagnostic distingue modèle arrêté, tunnel indisponible, accès révoqué ou expiré.

Toutes les conversations sont synchronisées sur le serveur par accès personnel.
Les copies locales et les réglages sont chiffrés par Windows DPAPI pour votre compte Windows.
Le thème, la police, la taille, la réflexion, la navigation et le brouillon du correcteur
sont conservés après fermeture. Les historiques sont inclus dans les sauvegardes du serveur.
Le dossier LOCALAPPDATA/QwenClient est conservé pour la compatibilité.
Un historique illisible n’est jamais remplacé silencieusement : l’action de récupération
conserve le fichier chiffré original. Deux fenêtres ne peuvent pas écraser la même
révision ; en cas de conflit, exportez votre travail puis rechargez l’application.
L’export JSON est lisible, sans chiffrement. Maximum : 200 conversations et 9 Mo.
La fermeture normale attend l’enregistrement complet de l’historique.

Dans Réglages > Mises à jour, cliquez Vérifier puis Mettre à jour le client si une version est
proposée. Signature Ed25519, taille et SHA-256 sont vérifiés avant installation.
Les clés personnelles sont conservées. L’ancienne version reste archivée et est
restaurée si la nouvelle fenêtre ne confirme pas son démarrage. Une mise à jour
peut être lancée pendant une discussion ou une requête API : la génération est
interrompue au redémarrage du client. Un changement d’adresse attend la fin des requêtes.
Une mise à jour conserve le dossier de votre EXE et lui donne le nom normal
« Accès serveur Fred VERSION - NOM DU CLIENT.exe », comme un nouveau téléchargement.
Le nom du client est celui enregistré dans l’interface d’administration lors de la création
ou du dernier renommage. Exemple : « Accès serveur Fred 3.5.16 - Fred.exe ».
La version correspond au binaire téléchargé ou installé.
L’ancien EXE est conservé dans « Sauvegardes client Fred » pour le retour automatique
en cas d’échec du démarrage. Les suffixes .previous ne sont plus ajoutés au nom.

Gardez l’application ouverte pour son API locale, généralement
http://127.0.0.1:17841/v1. Un port libre jusqu’à 17850 est choisi si nécessaire.
Après mise à jour depuis une ancienne version, recopiez cette adresse dans vos
applications ou utilisez Ajouter à OpenCode 2 / Ajouter à Hermes pour l’actualiser.
Utilisez la clé locale affichée dans API locale. Elle diffère de la clé distante intégrée.
Fermer l’application ferme le tunnel et l’API locale.

Votre EXE est votre clé d’accès. Remettez-le uniquement à son destinataire.
La base dist/Accès serveur Fred.exe ne contient aucun profil et sert à la compilation.
Distribuez exclusivement les EXE personnels générés dans la console serveur.

Technologies : Python 3.12, HTML/CSS/JavaScript dans pywebview/WebView2 et WireGuard Go
avec pile réseau en mémoire. Aucun pilote VPN ni droit administrateur côté client.
Microsoft Edge WebView2 Runtime doit être présent.
Sources applicatives MIT : LICENSE.txt ; dépendances : THIRD-PARTY.txt.
Compilation Windows x64 : Build-WireGuard.ps1 puis Build-Client.ps1.
Audit et vérifications : ../lanceur/AUDIT-FRED.txt.

Interface 3.5.0 : mise en page Markdown, choix de police et taille du texte,
correcteur et diagnostic de connexion dans le voyant supérieur. Navigation compacte, thèmes clair/sombre/Windows, menus contextuels,
projets par onglets et filtres de tâches. Voir ../lanceur/REFONTE-INTERFACE.txt.

Un EXE distinct par personne ou PC utilisé simultanément. Copier le même EXE
partage la même identité WireGuard et peut détourner les réponses vers l’autre poste.
Aucun plafond de tokens par réponse : la capacité de contexte du modèle reste finie.
Voir ../lanceur/NOUVEAUTES-3.5.0.txt.

Version 3.5.5 : profils Général/Rédaction/Code/Analyse/Recherche supprimés.
Les anciennes discussions sont effacées du serveur et des copies locales lors de
la mise à jour, sans archive. Les nouvelles discussions restent synchronisées.

et mémorisée, fichiers TXT/MD/PDF texte/DOCX joints au chat (2 Mo par fichier,
4 pièces maximum), images PNG/JPEG/WebP si la vision du modèle est activée.

confirmation d’enregistrement. Les titres, tableaux et blocs de code des réponses
suivent également la taille choisie.

Version 3.5.8 : mise en page adaptative, correcteur utilisant la largeur et la
hauteur disponibles, texte et résultat côte à côte sur grand écran et empilés
sur petite fenêtre. La fenêtre initiale respecte la zone de travail de Windows.

Version 3.5.21 : conversation vocale Windows. Installer la conversation une fois
(environ 138 Mo), puis Conversation : parler, attendre la fin du tour, Fred répond

microphone. La voix serveur se pilote dans Démarrage et surveillance.

Version 3.5.18 : sources consultables et notifications.
Dans Projets, développez « Rechercher un passage dans les documents », puis
cliquez « Ouvrir le passage cité » pour vérifier le texte exact, sa révision
et sa page lorsqu'elle est connue. Une ancienne citation signale si le document
a été modifié ou supprimé. Les résultats de tâches conservent leurs sources.
La rubrique Notifications retrouve vos alertes de tâches et documents sur le
serveur. Lecture, préférences par type et rattrapage sont synchronisés.
Les sauvegardes du serveur incluent cette boîte. Voir le mode d'emploi
../lanceur/RECHERCHE-NOTIFICATIONS.md et les preuves ../preuves/lots-6-8/VALIDATION.md.

Version 3.5.23 : la synchronisation automatique de l'historique conserve
la conversation vocale et la lecture de la réponse. Le tour suivant attend
la fin de cette synchronisation avant d'être envoyé.

Version 3.5.22 : chaque conversation est traitée par Hermes sur le serveur,
avec un profil par accès et une session par discussion. Les recherches et
outils apparaissent comme progression ; leurs commentaires ne sont pas lus
par la voix. Une action demandant votre accord présente son effet et les choix
Autoriser cette action ou Refuser. Une autorisation ne vaut que pour cette
action. Les réponses finalisées sont retrouvées après une coupure de connexion,
sans relancer le travail. Le correcteur utilise également Hermes.
Un accord en attente est retrouvé après la réouverture du client, en conservant
la conversation et le projet concernés.

Le client annonce le protocole conversationnel 4. Les profils et manifestes
de mise à jour au format 3 restent acceptés pour conserver les accès et
permettre aux anciennes versions de télécharger la nouvelle application.
Une indisponibilité de Hermes est signalée par le serveur ; les copies locales
chiffrées et les mécanismes de mise à jour sont conservés.
