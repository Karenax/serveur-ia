# Clients Windows et Linux : état de la parité

État du code et des recettes du 18 novembre 2026. Les deux clients utilisent Tauri et les sources communes de l’interface Kiara. La solution de retour Qt a été abandonnée ; le paquet Linux de recette utilise Tauri seul. L’unification du moteur de fenêtre réduit les différences à maintenir, mais ne rend pas automatiquement identiques les intégrations propres aux systèmes.

| Fonction | Windows | Linux | État de la vérification |
|---|---|---|---|
| Navigation, conversations et portail Projets | Interface commune dans Tauri / WebView2. | Interface commune dans Tauri / WebKitGTK. | Navigation fixe et parcours fictifs testés dans les deux moteurs. Après l'ajout de Notes, le candidat Linux reconstruit a été testé avec ses propres fichiers de Conversations et le portail compilé sur les trois résolutions ; les différences de moteur et de préférences locales peuvent modifier le rendu. |
| Zoom clavier et souris | Zoom natif WebView2 ; Ctrl + plus et Ctrl + 0 vérifiés avec un brouillon fictif. | Zoom WebKitGTK ; Ctrl + plus, moins, 0 et molette vérifiés avec clavier français et brouillons fictifs. | Même usage principal, incréments distincts : 10 % sous Windows et 20 % sous Linux dans les essais. |
| Données et brouillons locaux | Chiffrement DPAPI lié au compte Windows. | Chiffrement avec une clé conservée dans Secret Service. | Les relais Windows extraits conservent un profil et des brouillons fictifs avec DPAPI natif lors d’un aller-retour entre versions. Sous Linux isolé, le cycle d’installation et de retour a conservé les fichiers fictifs avec un trousseau Secret Service. La mise à jour via l’installateur Windows a été exercée sous Wine et reste à vérifier sur Windows natif. Les données locales restent propres à chaque appareil. |
| Microphone des réunions | Capture navigateur et composant Windows natif disponibles selon la configuration. | Capture navigateur WebKitGTK avec autorisation explicite ; secours PCM si nécessaire, dans le studio et dans le panneau audio du projet. | Les fragments sont récupérables après interruption. Pour une capture terminée normalement et importée, l'utilisateur peut libérer sa copie locale après vérification du serveur ; les captures sans preuve de fin restent conservées. Les deux Tauri ont été testés avec une tonalité virtuelle et vingt navigations de 720p à WQHD, ainsi qu'avec une interruption de la suppression. Un aller-retour fictif avec le portail précédent conserve les fragments, mais celui-ci les présente à tort comme une séance. Les derniers fragments non sauvegardés peuvent manquer et le matériel réel reste à qualifier. |
| Son système des réunions | Composant natif Windows avec boucle audio, sous réserve de configuration et de test matériel. | Le candidat Tauri crée, à la demande, une source temporaire reliée à la sortie par défaut et l’enregistre sur une piste distincte du microphone. Il utilise `pactl` et un serveur qui accepte les modules de boucle PulseAudio ; tous les sons de cette sortie sont captés. | Sur sources virtuelles, les deux pistes ont été enregistrées et distinguées dans le Studio, de 720p à WQHD, avec PulseAudio puis PipeWire-Pulse 1.0.5 isolé ; la reprise hors ligne et après fermeture brutale a conservé les fragments fictifs. La qualification sur matériel réel et sur d’autres environnements reste à faire. Le candidat n’est pas installé en production. |
| Conversation vocale Low | Reconnaissance sur le PC ; voix fournie par le serveur. | Même principe avec les composants audio Linux. | Les appareils physiques doivent être testés sur chaque poste. |
| Conversation vocale Max | Exécution possible sur le PC ou sur le serveur selon les composants disponibles. | Exécution sur le serveur Kiara ; le complément Max local Windows n’est pas porté. | Différence fonctionnelle connue : le bouton local n’est pas proposé sous Linux. |
| Interruption de la voix en parlant | Disponible si le moteur et l’équipement prennent en charge l’annulation d’écho. | Désactivée : le microphone reprend après la réponse de Kiara. | Différence volontaire pour éviter la retranscription des haut-parleurs ; ne pas annoncer une parité complète. |
| Capture d’écran | Sélection de zone par le mécanisme Windows. | Portail du bureau, puis sélection locale de zone et aperçu. | La sélection et l’annulation ont été testées ; le portail Linux peut capturer tout l’écran et en conserver une copie locale. |
| Mise à jour du client | Installateur Windows et mécanisme de mise à jour associé. | Installation manuelle d’une nouvelle archive ; le raccourci est réorienté. | Sous Linux isolé à 720p, aller-retour entre candidats Tauri 4.0.10 et 4.0.12 avec profil, brouillons et fragment fictifs, service Secret Service isolé et dépendances préinstallées. Sous Wine, les installateurs 4.0.11 et 4.0.12 ont effectué le même aller-retour avec fichiers chiffrés fictifs. Les migrations entre versions publiées sur Linux physique et sous Windows natif restent à qualifier. |

La parité doit être évaluée fonction par fonction et sur les matériels réels. Les preuves, versions et réserves sont détaillées dans [AVANCEMENT.md](AVANCEMENT.md). Les différences Max local, interruption vocale, qualification de la capture système et mise à jour sont des travaux distincts du remplacement de Qt par Tauri.

Les brouillons et fragments audio du portail dépendent de l’origine locale, notamment du port du relais. Pour un profil Tauri existant sans port enregistré, le candidat inventorie les origines et enregistre l’unique origine contenant des données. Si plusieurs origines sont présentes, si une base est inconnue ou si un port est indisponible, le démarrage s’arrête sans déplacer les données ; la fusion reste expérimentale et désactivée par défaut. Ce parcours n’inventorie ni ne migre le stockage d’un autre moteur. La conservation du profil chiffré ne prouve pas celle des données du portail.
