# Moteurs tiers

Depuis le 19 octobre 2026, le moteur actif et enregistré par défaut est **Strata 0.1.45.3**, dans `strata-0.1.45.3/engine-cuda12/`, issu du paquet officiel Strata 0.2.0-beta. Les DLL CUDA sont colocalisées avec le moteur. Le serveur Python corrigé, le tokenizer, le profil experts et l’encodeur P2200 restent sous `strata-0.1.43.1/` ; ce dossier est toujours indispensable. Voir [activation, empreinte, preuve et retour arrière](../maintenance/2026-10-19-strata-0.1.45.3/README.md).

Le [correctif des arguments XML/JSON mixtes et des champs obligatoires](../maintenance/2026-10-16-outils-mixtes/README.md), d'abord préparé sans interruption, a ensuite été [activé par un redémarrage demandé par l'utilisateur](../maintenance/2026-10-16-activation-outils-mixtes/README.md). Les 367 tests couvrent les cas fautifs et les essais réels après relance passent. Les patchs doivent être repris dans l'ordre : booléens, puis formats mixtes.

Le 16 octobre 2026, un [correctif local du parseur serveur Strata](../maintenance/2026-10-16-outils-booleens/README.md) a été installé : normalisation de `True`/`False` uniquement pour les arguments déclarés booléens, formats XML/JSON et streaming. Le binaire CUDA reste celui de la distribution officielle. Patch, sauvegarde de la source et empreintes sont conservés dans le dossier de maintenance ; 355 tests et des appels d'outils réels passent. Vérifier ce correctif lors d'une prochaine mise à jour des sources tierces. Le cache actif conserve désormais jusqu'à 20 conversations sauvegardées, dans un budget global de 30 Gio.

Le 13 octobre 2026, le moteur de production Flash-Next est devenu la distribution officielle CUDA 12 de Strata **0.1.43.1**, installée dans `strata-0.1.43.1/` avec sa source serveur, ses bibliothèques CUDA 12.9, son tokenizer et le profil experts testé. Les modèles restent dans `strata-data/`. La preuve de déploiement et la sauvegarde précédente sont dans `maintenance/2026-10-13-strata-0.1.43.1/`. L'ancien moteur P100 personnalisé reste disponible.

Depuis l'essai du 14 octobre, l'encodeur visuel P2200 utilise une compilation locale séparée dans `strata-0.1.43.1/vision-p2200-cuda12.4/` : CUDA 12.4.131, `61-real`, sources et empreinte dans son `BUILD.json`. L'encodeur officiel échouait à initialiser CUDA avec le pilote du poste et continuait sur CPU. Le moteur texte officiel reste inchangé. Le projecteur vérifié est dans `strata-data/vision/`. Voir [recette, preuves, mesures RAM/VRAM et retour arrière](../maintenance/2026-10-14-vision/README.md).

`moteurs.json` référence les six dépôts historiques et leurs modifications ; il ne décrit pas la distribution officielle actuellement chargée. Pour celle-ci, suivre [le guide de mise en service](../maintenance/2026-10-19-strata-0.1.45.3/README.md) et l’empreinte de `production.json`. La preuve actuelle décrit le chemin et l’empreinte du processus réellement actif.

Pour chaque entrée de `moteurs.json`, cloner `remote` dans `directory`, extraire le commit `patch_base`, puis appliquer le patch depuis ce dossier avec `git apply --binary <chemin-du-projet>/dependances/<patch>`. Copier ensuite les éventuels fichiers indiqués par `additional_directory` dans le moteur.

Les patchs contiennent les modifications locales, y compris les changements committés depuis la base. Les outils CUDA, modèles et environnements Python ne sont pas sauvegardés ici. Relancer `Sauvegarder-Dependances.py` avant un commit pour actualiser cet instantané.
